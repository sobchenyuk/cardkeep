# CardKeep — опис проєкту і ТЗ

## Навіщо

Гаманець для скидочних і накопичувальних карток, у якому **дані належать користувачу**.

Передісторія: Stocard закрився, код переносу в інший сервіс не спрацював, і близько 20 карток зникли без можливості відновлення. CardKeep має зробити таку ситуацію неможливою: картки лежать на телефоні, а повна копія в будь-який момент вивантажується одним архівом, який відкривається навіть без застосунку.

Принципи:

- **Без реклами.** Це інструмент, а не платформа для показів.
- **Простота.** Не гірше за аналоги (SuperCards, Catima), але простіше.
- **Offline-first.** На касі в підвалі без зв'язку картка все одно відкривається.
- **Один дизайн для Android та iOS.** Веб-застосунок, який виглядає і поводиться як нативний.
- **Без магазинів застосунків.** Установка через браузер (PWA).

## Етапи

| Етап | Що | Бекенд |
|---|---|---|
| **MVP (зараз)** | PWA на GitHub Pages, усі дані локально в IndexedDB, експорт/імпорт ZIP | немає |
| v2 | Вхід через Google (Firebase Auth), синхронізація карток (Firestore), фото в Cloudflare R2, поділитися карткою за посиланням | Firebase + R2 + мінімальна функція видачі signed URL |
| v3 | Можлива обгортка в нативний застосунок (Capacitor), монетизація серверних функцій (синхронізація, сімейні картки) | — |

## MVP: функціональні вимоги

### 1. Модель картки

| Поле | Обов'язкове | Примітка |
|---|---|---|
| `id` | так | UUID |
| `title` | так | назва картки / магазину |
| `code` | ні | значення коду (рядок), картинка коду **не зберігається** — генерується щоразу |
| `codeFormat` | ні | `qr`, `ean13`, `ean8`, `code128`, `code39`, `upca`, `pdf417`, `datamatrix`, `aztec`, `none` |
| `description` | ні | вільний текст, нотатки |
| `categoryId` | ні | посилання на категорію; без категорії → група «Без категорії» |
| `frontPhoto` | ні | лицьова сторона, стиснутий WebP (Blob) |
| `backPhoto` | ні | зворотна сторона, стиснутий WebP (Blob) |
| `color` | ні | колір плашки, якщо фото немає (за замовчуванням — з назви) |
| `createdAt`, `updatedAt` | так | ISO-дати |

Категорія: `id`, `name`, `order`.

### 2. Головний екран

- Список карток **за алфавітом** (за `title`, з урахуванням української/кириличної локалі).
- **Пошук** за назвою зверху (миттєвий, без кнопки).
- Перемикач вигляду: «За алфавітом» / «За категоріями». У режимі категорій — групи, всередині кожної картки за алфавітом; картки без категорії в окремій групі «Без категорії» в кінці.
- Картки в списку виглядають як картки в Google Wallet: фото лицьової сторони або кольорова плашка з назвою.
- Кнопка «Додати картку».
- Нижня панель навігації (футер): Картки · Категорії · Налаштування.

### 3. Додавання / редагування картки

- **Сканування коду**:
  - жива камера (на HTTPS доступна) — нативний `BarcodeDetector`, де він є, інакше ZXing;
  - розпізнавання коду з фото (якщо в камери немає доступу або сканування не вдалося);
  - **ручне введення** коду і вибір формату.
- Фото **лицьової і зворотної сторони** — обидва необов'язкові. Можна зняти камерою або вибрати з галереї.
- Поля: назва, опис, категорія (вибір зі списку + «Створити нову»).
- Видалення картки з підтвердженням.

### 4. Стиснення фото

Тільки **на телефоні**, до збереження:

- зменшення до ~1200 px по довшій стороні;
- WebP, якість ~0.75 (fallback JPEG, якщо WebP-кодування не підтримується);
- ціль: 100–200 КБ на фото;
- виконувати в Web Worker через `OffscreenCanvas`, де доступно, щоб не блокувати інтерфейс; інакше звичайний `canvas`.

### 5. Екран картки (bottom sheet)

- Відкривається як **полотно, що виїжджає знизу**. Зверху — риска-ручка; **свайп униз закриває**.
- Зверху — **слайдер фото**, свайп вліво/вправо: лицьова → зворотна. Завжди відкривається на лицьовій.
- Якщо фото немає — кольорова плашка з назвою.
- Під слайдером — **код**: великий, на **білому фоні навіть у темній темі** (сканери погано читають інвертований код). Під кодом — його значення текстом.
- Далі **назва** і **опис**: видно 4 рядки, решта скролиться.
- Далі **мапа** (див. п. 7).
- Кнопки: Редагувати, Поділитися (у MVP — системне «Поділитися» з назвою і кодом; посилання-імпорт — у v2).
- Під час показу картки — підвищити яскравість неможливо з вебу, тому лише великий контрастний код.

### 6. Категорії

- Окремий екран: створити, перейменувати, видалити, змінити порядок.
- При видаленні категорії картки не видаляються, а стають «Без категорії».
- У MVP: **одна категорія на картку** (див. «Відкриті питання»).

### 7. Мапа

- OpenStreetMap (Leaflet), без API-ключів.
- Пошук закладів **за назвою картки поблизу** користувача:
  - з дозволом геолокації — пошук у радіусі навколо поточної позиції (Overpass API за `name`/`brand`), найближчі точки на мапі;
  - без геолокації — пошук за назвою (Nominatim), без прив'язки до позиції.
- Кнопка «Відкрити в картах» (системний застосунок мап).
- Мапа завантажується ліниво — лише коли користувач до неї доскролив.
- Дотримуватися правил використання Nominatim/Overpass: не частіше 1 запиту/с, кешувати результати.

### 8. Експорт / імпорт

- **Експорт** — ZIP-архів `cardkeep-backup-YYYY-MM-DD.zip`:

  ```
  cards.json           # картки + категорії + версія формату
  photos/
    <cardId>-front.webp
    <cardId>-back.webp
  README.txt           # пояснення формату людською мовою
  ```

  Архів має бути зрозумілим **без застосунку**: розпакував — бачиш JSON і звичайні картинки.
- **Імпорт** — вибір ZIP, перевірка версії формату, попередній перегляд («Буде додано N карток»), режими: «Додати до наявних» / «Замінити все». Дублікати (той самий `code` + `title`) — пропускати.
- Нагадування в налаштуваннях: дата останнього експорту.

### 9. Сповіщення (toast)

Кожна дія має видимий зворотний зв'язок:

- процес: «Стискаємо фото…», «Зберігаємо…», «Готуємо архів…»;
- результат: «Збережено», «Архів готовий»;
- помилка: зрозумілий текст + кнопка «Повторити».

Помилки, які треба обробити: немає доступу до камери, код не розпізнано, фото не вдалося стиснути, IndexedDB переповнена / недоступна (приватний режим), пошкоджений архів, несумісна версія формату, немає мережі для мапи, геолокацію заборонено.

### 10. Тема

- Світла / темна / системна. **За замовчуванням — системна.**
- Перемикач у налаштуваннях, вибір зберігається локально.

### 11. PWA

- Маніфест, іконки, `display: standalone`, установка на головний екран (Android і iOS).
- Service worker: увесь застосунок доступний офлайн; тайли мапи — кеш з обмеженням розміру.
- Повідомлення про нову версію: «Доступне оновлення — Оновити».

## Дизайн

- Як застосунок, а не сайт: на весь екран, без адресного рядка, нижня навігація, системний шрифт.
- Строгий: один акцентний колір, без градієнтів, без зайвих тіней, без «шаблонного AI-вигляду».
- Без виділення тексту й синього підсвічування при натисканні (`-webkit-tap-highlight-color`, `user-select` на елементах керування).
- Плавні анімації полотна (bottom sheet), жести свайпу.
- Безпечні зони (`env(safe-area-inset-*)`) для iPhone з вирізом.
- Один дизайн для Android та iOS.

## Нефункціональні вимоги

- Мобільний перший; мінімум 360 px ширини.
- Холодний старт до інтерактиву < 2 с на середньому телефоні.
- Доступність: контраст AA, розміри зон натискання ≥ 44 px.
- Жодних трекерів і аналітики третіх сторін.

## v2 (не в MVP)

- Firebase Auth (Google) — лише для розділення користувачів.
- Firestore для даних карток (вбудований офлайн-кеш і синхронізація).
- Cloudflare R2 для фото: клієнт стискає → черга на телефоні → завантаження за тимчасовим signed URL. Ключі R2 тільки на сервері.
- Подія `online` браузера замість вебсокетів для перевірки зв'язку. Kafka не потрібна.
- **Поділитися карткою за посиланням**: снапшот (копія) картки; одержувач відкриває посилання, входить і отримує ту саму картку з тим самим кодом. Бонуси накопичуються в магазині на один рахунок.
- iOS не синхронізує у фоні — вивантаження черги при наступному відкритті застосунку.
